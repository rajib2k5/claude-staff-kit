# Marketplace comparison: staff-kit and claude-plugins-official

## 1. Scope

- Compared the staff-kit components (25 skills, 19 agents, 12 commands, 19 rule files, 2 hook scripts) with the `claude-plugins-official` catalog on 2026-10-11, revised 2026-10-12 after the packaging fixes. The catalog holds 315 entries.
- Method: read catalog descriptions, ran keyword searches over entry names and descriptions, and read the package layout of superpowers 6.4.1 as a structural reference. The source of every other marketplace plugin was not read, so "what the marketplace plugin adds" is what its description claims.
- Not measured: the token cost of any marketplace plugin, and which skill Claude picks when a kit skill and a marketplace skill both match.

## 3. Unique to the kit

- **Adversarial validation as the highest-tier rule.** `adversarial-validation.md` outranks every other rule, and the validator agent is pinned to Opus in its frontmatter. A flagged blocker must be reproduced before anyone acts on it, because validators produce false positives too.
- **Explicit model routing per subagent.** All 19 agents declare a `model:` (15 Opus, 4 Sonnet), and `scripts/validate.sh` rejects an agent without one. The stance fits a personal Claude Max plan, where token spend is the constraint: mechanical work goes to Sonnet and validation never drops a tier.
- **Irreversibility ladder T0 to T4 and definition-of-done thresholds.** Every change sits on a ladder from reversible (T0) to unrecoverable (T4), and T3 and T4 never run on inference. `definition-of-done.md` holds the numbers, for example 400 substantive lines per PR and a coverage floor of 70 overall and 90 on critical paths.
- **Destructive-ops guard across every technology.** One PreToolUse hook covers SQL, dbt, git, shell, Terraform, Kubernetes and cloud CLIs, with an ask tier and a deny tier. `node --test hooks/*.test.js` ran 121 tests and 121 passed on 2026-10-11.
- **Evidence-gated dual-channel validation.** One channel researches official documentation, the other probes runtime behaviour, and a claim is accepted only when both agree. A Stop hook flags completion claims that have no executed command behind them; it is advisory and never blocks.
- **Data-platform depth.** Snowflake RBAC, pruning and cost, dbt layering and incremental-model rules, metric definitions, and grain and fan-out hunting. By catalog description, no marketplace entry packages these as standards or audit workflows.
- **Simplified Technical English.** The `simple-english` skill applies the ASD-STE100 rules to documentation, runbooks and error messages. No catalog entry mentions Simplified Technical English.
- **Tiered contexts.** Tier 0 loads always, tier 1 loads per role and tier 2 loads per domain, and the rest is read on demand. The aim is that a session pays only for the context it needs.
- **Cortex CLI adapter.** `adapters/cortex` documents how `~/.cortex/` maps onto the kit's directories, and `bootstrap.sh` registers the skill directory and seeds the CLI's own rule and memory store. The seeding step exists because Cortex memory is imperative (`cortex ctx`) and cannot be symlinked.

## 5. Gaps the comparison exposed

- **No evals.** The 121 tests cover the guard hook only. CI checks structure (JSON, frontmatter, shell syntax), not whether a skill triggers on the right prompt or produces the right output. The catalog's `skill-creator` advertises evals; see `RECOMMENDED_PLUGINS.md`.
- **Hooks are Node-only.** Both hook scripts run through `node`, no manifest declares a minimum Node version, and CI uses Node 20. superpowers wraps its hook in a `.cmd` script, which suggests it handles Windows. If `node` is missing the command exits non-zero; Claude Code treats any exit code other than 2 as a non-blocking error and shows the stderr to the user, so the guard fails open with a visible message rather than silently.
- **Prefixed names read badly in plugin mode.** Plugin skills are invoked as `plugin:skill`, so `staff-ship` becomes `staff-kit:staff-ship`. Commands follow the same pattern (`commit-commands:commit` is an observed example). The Cortex CLI already renders `staff-review` as `staff:review`. **TODO(unknown):** keep the prefix so all three install paths share names, or drop it in plugin mode only?
- **Rules and contexts are referenced by `~/.claude/...` paths.** In plugin mode the SessionStart hook injects a hint to read the same path under `${CLAUDE_PLUGIN_ROOT}/` when the `~/.claude` path does not exist. Three consequences. If a dotfiles install and the plugin both exist, the dotfiles copy wins silently, even when it is older. If the hook does not run, the rules are not found. Subagents do not receive SessionStart output, so an agent prompt that says "read `~/.claude/rules/...`" cannot find the file in plugin mode unless the rules are also present under `~/.claude`. Dotfiles mode has none of these problems and is the primary mode for this author; plugin mode is for sharing.
- **The SessionStart hook has a standing token cost.** Its stdout measured 3,589 characters in plugin mode and 3,146 in dotfiles mode (hook run with synthetic input on 2026-10-11). At about four characters per token that is on the order of 900 tokens at each session start; the conversion is an estimate, not a measurement. Adopted from superpowers: `hooks/hooks.json` and `scripts/merge-settings.py` now match SessionStart on `startup|clear|compact` only, so a resumed session (which already holds the policy in its transcript) does not pay for it again. The PreToolUse matcher stays empty (every tool): the validator showed that a tool-name list would silently drop the guard's checks on `Artifact` deletes and on MCP SQL tools (the guard inspects any tool whose name contains sql, query, snowflake, bigquery, postgres, mysql or duckdb), which its own tests cover.
- **The guard sees only Claude Code tool calls.** It inspects `Bash`, `BashOutput`, the paths touched by `Write`, `Edit` and `NotebookEdit`, `Artifact` deletes, and the SQL handed to MCP tools whose names contain sql, query, snowflake, bigquery, postgres, mysql or duckdb. SQL run by Cortex Code after `snowflake-cortex-code` routes a prompt there, or by an MCP tool with a name outside that list, never reaches the guard. The skill-level rule (`destructive-ops-guard`) still applies, but without the hook backstop.
- **The Stop hook warned on its own policy text.** The policy quotes the forbidden phrases, the SessionStart output is saved in the transcript, and the Stop branch scanned the raw transcript tail, so it warned on turns that made no claim (39 times in one real transcript, found by the validator on 2026-10-12). Fixed in the kit: the hook strips its own blocks before scanning and honours `stop_hook_active`; `hooks/evolv-skills-enforcer.test.js` covers it. The `~/.claude` copy on the author's machine still has the old behaviour until it is reinstalled from the kit.
- **Co-installation with superpowers is untested.** `staff-debug` and superpowers `systematic-debugging` both trigger on "debug this", and `staff-tdd` and `test-driven-development` overlap the same way. **TODO(unknown):** which skill Claude picks when both match.
- **CI pinning.** Found unpinned in the first draft; `validate.yml` now pins `actions/checkout` and `actions/setup-node` to commit SHAs and installs `@anthropic-ai/claude-code@2.1.287`, per the kit's own `security.md`.
- **Attribution.** The enforcer hook header named `evolvconsulting/evidence-gated-validation` (a private repository) as the source of the bundled skill. The public source is `rajib2k5/evidence-gated-validation` (MIT, same author, same `SKILL.md` blob); the header now says so. The three skills that carry `license: MIT` in their frontmatter are the author's own, so `LICENSE` needs no further credit.
